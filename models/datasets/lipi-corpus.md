# Dataset card: Lipi page corpus

Images of pages (documents, receipts, ID cards, notes, whiteboards) with the four page corners and the page orientation, used to train and evaluate the page detector and the orientation classifier.

## Parts

| Part | Source | License | Use |
|---|---|---|---|
| Synthetic | Generated by [`ml/tools/synth.py`](../../ml/tools/synth.py) | Same as this repository (MIT) | Train, validation, test |
| ID cards | [MIDV-500](https://arxiv.org/abs/1807.05786) and MIDV-2019 (Arlazarov et al.), frames and corner labels taken from the copy in [`mapo80/DocCornerDataset`](https://huggingface.co/datasets/mapo80/DocCornerDataset) | CC BY-SA 2.5 (the authors' own `license.txt`) | Training only (2,400 frames); see [MIDV ID cards](#midv-id-cards-cc-by-sa-25) |
| Real photos | [A New Image Dataset for Document Corner Localization](https://data.mendeley.com/datasets/x3nm4cxr83) (Soheili, Mansouri and Baniadam Dizaj, 2020) | CC BY 4.0 | Training (a disjoint part), validation and test |

The real photos are not copied into this repository. [`ml/tools/fetch_mendeley.py`](../../ml/tools/fetch_mendeley.py) downloads them, checks the publisher's SHA-256 for every file, corrects EXIF rotation and keeps 512 px copies. Please cite the paper when you use them: https://ieeexplore.ieee.org/abstract/document/9116896/

## MIDV ID cards (CC BY-SA 2.5)

The first two detectors were trained on synthetic pages and the Mendeley photos. To add ID cards, a third source was considered: the Hugging Face dataset [`mapo80/DocCornerDataset`](https://huggingface.co/datasets/mapo80/DocCornerDataset), which re-publishes frames and corner labels from many sources. Its own licence information is not reliable, so each source inside it was checked against its upstream terms (checked 22 November 2026), and only what could be confirmed is used.

**Why the re-upload's licence was not used.** The dataset card said CC BY 4.0 when it was first published (17 December 2025) and was replaced on 8 January 2026 by `license: other` with a per-source table, while its `dataset_info.json` says MIT. Nothing there grants an MIT-compatible right, and a re-upload cannot grant more than the original source allows.

(The dataset card calls it "research use only", which is wrong in the more restrictive direction.) The source ID images are described by the authors as public domain or under public copyright licences. | **Yes** |
| MIDV-2019 (`midv2019_`) | 143 | Its own `license.txt` says CC BY-SA 2.5 | **Yes** |
| SmartDoc (`smartdoc_`) | 891 | Mixed: SmartDoc-QA is CC BY 4.0 (Zenodo record 5293201) and the 2015 Challenge 1 data is CC BY 4.0, but the 2015 Challenge 2 data is research only with redistribution forbidden. The dataset card cites the Challenge 2 paper while its first version said SmartDoc-QA, so it could not be shown which source these images came from. | No: provenance unconfirmed |
| COCO negatives (`negative_coco*`) | 5,685 | Images without a page, so there are no corners to learn from and the detector has no "no page" output. COCO's own site could not be read without JavaScript; each COCO image is a Flickr photo under its own licence, some of them non-commercial or no-derivatives, which the dataset card's "CC BY 4.0" does not reflect. | No: unusable and unverified |
| About 45 Roboflow Universe projects (`id_detections_`, `document_segmentation_*`, `card_*`, `receipt_*`, `book_*`, `bill_*` and others) | 33,956 | The licence belongs to each project, and the dataset records no owner or URL for any of them, only a name prefix. None could be verified, and attribution would be impossible. | No: unverifiable |

So 7,733 of the dataset's 48,265 images (16%) are usable, all of them ID cards.

**What is used.** A seeded random sample of 2,400 MIDV frames (2,356 MIDV-500 and 44 MIDV-2019), because the frames of one video are near duplicates and a sample is enough. Every sampled frame has all four corners inside the picture. Images are shrunk to a 512 px long side (all are 288 x 512 portrait frames) and the corners are put in the corpus order (top-left, top-right, bottom-right, bottom-left); orientation is unknown (`null`). They are used for training only, never for validation or testing. Built with [`ml/tools/fetch_midv.py`](../../ml/tools/fetch_midv.py) (`--seed 0 --count 2400`). The MIDV images are not redistributed by this repository; only the trained model is.

**Overlap with the held-out photos.** Every selected frame was compared with the real validation, test and training photos (1,058 images) by a 64-bit perceptual hash, dropping any within 8 bits. None matched: the closest MIDV frame is at distance 10 and the median is 18, while a shrunken, recompressed copy of a held-out photo, used as a control, is at distance 1. An exact byte comparison was not possible because the held-out copies are resized. The two datasets also come from different places (a Wikimedia-based mock ID set against photos of flyers and printed pages), so an overlap was not expected.

**What the licence asks.** Attribution: Arlazarov V.V., Bulatov K., Chernov T., Arlazarov V.L., "MIDV-500: a dataset for identity document analysis and recognition on mobile devices in video stream", Computer Optics 43(5), 2019, DOI 10.18287/2412-6179-2019-43-5-818-824; and Bulatov K., Matalov D., Arlazarov V.V., "MIDV-2019: challenges of the modern mobile-based document OCR", Proc. SPIE 11433, Twelfth International Conference on Machine Vision (ICMV 2019), 114332N, 2020, https://doi.org/10.1117/12.2558438 (citations taken from the authors' readme files; the Hugging Face card gives a different, incorrect venue for MIDV-2019). The source ID images come from Wikimedia Commons, credited in the authors' table (`ftp://smartengines.com/midv-500/documents.pdf`).

**Open question: ShareAlike.** CC BY-SA asks that adaptations of the material be shared under the same licence. This repository does not distribute the frames, only a model trained on them, and whether trained weights count as an adaptation is legally unsettled. The project owner was told this and chose to go ahead on that basis. The MIDV-trained models are therefore marked in their model card, and anyone redistributing them should make their own assessment.

## Synthetic generation

Pages are drawn upright with Noto Sans, Noto Serif and Noto Sans Mono (SIL Open Font License) in Latin, Devanagari and Bengali, using a short built-in word list. Each page is placed on a procedural background (flat, wood, gradient, tiles, clutter, dark) through a random pinhole camera (rotation of any multiple of 90 degrees plus tilt), with paper lighting, cast shadows, a drop shadow, optional finger occlusion, blur, sensor noise, colour cast and JPEG compression. The camera is known, so the corner labels are exact. No third-party images are used.

## Annotation

One JSON object per line; see [`ml/lipi_eval/corpus.py`](../../ml/lipi_eval/corpus.py). `quad` holds the page corners in image pixels, ordered top-left, top-right, bottom-right, bottom-left as seen on the image. `orientation` is the number of 90 degree clockwise rotations that make the flattened page upright; it is `null` for real photos, which are not labelled for it.

## Splits

Splits are fixed by generator seed, so they can be recreated exactly.

| Split | Part | How |
|---|---|---|
| train | synthetic | `--seed 1`, `--count 20000` |
| val | synthetic | `--seed 2`, `--count 1000` |
| test | synthetic | `--seed 3`, `--count 2000` |
| val | real | first 100 images of `fetch_mendeley.py --seed 0` |
| test | real | the following images (up to `--count 400`; 287 usable) |
| train | real | the images after those 400 in the same shuffle: `fetch_mendeley.py --seed 0 --count 800 --train-from 400` (671 usable) |
| train | ID cards | 2,400 sampled MIDV frames, `fetch_midv.py --seed 0 --count 2400` |

The real training images come after the validation and test pool in the same seeded shuffle, so the three real splits never overlap (checked by image id). The first detector, trained on synthetic data only, reached a real validation IoU of about 0.74; adding the 671 real training photos (repeated 10 times per epoch) lifted it to 0.91, so the real photos matter. The real validation split chooses the checkpoint; the real test split is only used for the final numbers.

## Limitations

- The synthetic pages come from a few templates and a small vocabulary, and the backgrounds are procedural. Scores on the synthetic test split overstate real-world accuracy; use the real split for that.
- The real set contains many posters, flyers and printed pages with Persian and Arabic text, a few partly out of frame, and hands in view. It has fewer receipts, ID cards and handwritten notes than the app targets.
- A few real images are skipped when their corner labels cannot be matched to the image (for example, ambiguous EXIF rotation).
- All pages are rectangular and flat; curled pages and books are not covered yet.
